term: Agent Loop
zh: 代理迴圈
oneline: 拿到目標 → 判斷 → 下指令 → 執行 → 看結果 → 再判斷，跑到它說完成為止。

## 定義

代理迴圈是一支**由工程師撰寫的程式**，把模型的輸出接回模型的輸入，讓它可以連續行動。五個位置：

```flow
Goal / Task | 接收任務：「把這三家的財報數字整理成表」
Reasoning | 模型判斷下一步該做什麼
Function Calling | 模型寫出固定格式的指令
Tool Execution | 程式真的去執行那道指令
Observation | 執行結果回填給模型，進入下一輪
```

跑完 Observation 就回到 Reasoning，==直到模型宣告完成，或撞到人設定的輪數上限==。

## 為何會出現

模型一次只能吐一段文字。[[tool-use|工具呼叫]]讓那段文字可以觸發真實動作，但做完一個動作之後呢？結果要送回哪裡？誰決定還要不要繼續？

[[react|ReAct]] 提出了「想一步、做一步、讀結果、再修正」的想法，代理迴圈就是**它的工程化版本**——把那個想法變成一支真的會跑的程式。

## 金融背景怎麼理解

這個迴圈是整套系統裡**唯一完全由你控制的部分**，也因此是治理最好下手的地方。

模型的行為你改不了（那是模型公司的事），但迴圈的這幾個旋鈕都在你手上：

- **跑幾輪要停**——上限設 5 輪還是 50 輪，差別是出錯時它已經做了幾件事
- **配哪些工具**——給不給寫入權限、給不給對外寄送
- **第幾步要人簽核**——見 [[human-in-the-loop|人類介入審核]]
- **每一輪留不留紀錄**——事後追查的唯一依據

> [!提醒] 最常被誤會的一句
> 「AI 自己一直做下去」聽起來像模型有自主意志，實際上是==有人寫了一個 while 迴圈，而且沒設停止條件==。跑幾輪從來不是模型的天性，是設計階段的選擇。

延伸到極端就是[[autonomous-agent|自主代理]]：迴圈更長、人看得更少。差別只是程度。
