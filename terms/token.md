term: Token
zh: 詞元
oneline: 文字被切成的最小單位，也是計費單位。

## 定義

Token 是模型處理文字的**最小單位**。一段文字進到模型之前，會先被切開：

```flow
原文 | 客戶王小明於2019年開戶
切成 token | 客戶 / 王 / 小 / 明 / 於 / 2019 / 年 / 開 / 戶
模型看到的 | 九個編號，不是九個字
```

它**不等於「字」也不等於「詞」**。英文常見的切法是一個詞或詞根一個 token，中文則常常==一個字就吃掉一個以上的 token==。

## 為何會出現

模型沒辦法直接吃無限長的文字，得先切成可以計算的離散單位，才能做注意力運算。切太細（一個字母一個）序列會爆長，切太粗（一個句子一個）詞彙表會爆大——token 是這兩者之間的折衷。

一旦文字變成 token，「一次能放幾個」就成了硬性上限，那就是 [[context-window|上下文視窗]]。

## 金融背景怎麼理解

**報價單上的數字幾乎都是以 token 計。** 這是它跟你的預算最直接的關係。

三件實務上會咬到你的事：

**第一，中文比英文貴。** 同樣意思的一段話，中文用掉的 token 通常是英文的 1.5 到 2 倍。所以拿英文報價估中文用量，會低估。

**第二，輸入和輸出通常分開計價，而且輸出比較貴。** 一份要它「讀 50 頁文件，回答一句話」的任務，成本壓在輸入；「給一個標題，寫三千字報告」則壓在輸出。估算前先看清楚任務形狀。

**第三，==對話越長，每一輪都越貴==。** 這點最容易被忽略——每一輪對話都要把先前的內容整份重送一次，所以第 20 輪的成本遠高於第 1 輪。長對話或長文件的代理任務，成本不是線性成長的。

> [!提醒] 常跟 Context Window 搞混
> **token 是「單位」，[[context-window|context window]] 是「一次能放幾個」。**
>
> 就像「張」和「這個資料夾放得下幾張」——==兩者是量詞和容量的關係，不是同義詞==。
