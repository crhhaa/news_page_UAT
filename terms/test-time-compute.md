term: Test-time Compute
zh: 推論時運算
oneline: 把運算花在回答的當下，而不是只花在訓練。

## 定義

推論時運算指的是**模型在「回答你的那一刻」所投入的計算量**——相對於訓練時投入的計算量。

同一個模型，可以在回答時多做很多事：

```flow
想更久 | 產生更長的推導過程再作答
想很多次 | 同一題產生五個答案，挑最好的
自我檢查 | 答完再驗算一次，錯了重來
```

這些都不需要重新訓練模型，==只需要在使用當下多付錢==。

## 為何會出現

過去讓模型變強的路徑只有一條：**把模型訓練得更大**。參數更多、資料更多、訓練算力更多。但這條路的成本以億美元計，而且開始出現邊際效益遞減。

於是有人問了另一個問題：==既然訓練完的模型能力已經固定，能不能在使用時多榨出一點？==

答案是可以。同一個模型，讓它多想、多試、自己檢查，難題的正確率就明顯上升。[[reasoning-model|推理模型]]就是把這件事訓練成模型的本能，而不是靠外部提示。

## 金融背景怎麼理解

**這件事的意義主要在成本結構，而不是技術。**

| | 以前 | 現在 |
|---|---|---|
| 錢花在哪 | 訓練端（一次性） | ==使用端（每一次）== |
| 呼叫成本 | 每次都便宜且固定 | 難題每次都要再付一次 |
| 預算怎麼編 | 買斷／訂閱思維 | **變動成本思維** |

以前是一次投資、之後每次呼叫都很便宜。現在是**每碰到一次難題，就要再付一次「想更久」的錢**。

這對編預算的影響很直接：==你沒辦法只看「每千 token 多少錢」來估算==。同樣一個模型，處理一份簡單文件和一份需要交叉比對的合約，成本可能差十倍以上，而差別來自它自己決定要想多久。

> [!提醒] 導入時要問的兩題
> **第一，這個應用的成本會隨案件難度浮動嗎？** 會的話，估算要用最壞情況，不能用平均。
>
> **第二，==有沒有辦法設上限？==** 多數模型 API 可以限制推理預算。沒設的話，一份異常複雜的輸入可能吃掉你預期十倍的費用，而且你事前不會知道。

一句話總結：**「多想」通常更準，也更慢、更貴。要按任務風險配置，不是全開。**
