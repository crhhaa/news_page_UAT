term: ReAct
zh: 想一步做一步
oneline: 想一步、做一步、讀結果、再修正——今天代理迴圈的原型。

## 定義

ReAct = **Reasoning（推理）＋ Acting（行動）**，把兩者交錯進行，而不是先想完再做：

```flow
Thought | 我需要先查這家公司去年的營收
Action | 呼叫工具：查詢財報(公司=2330, 年度=2025)
Observation | 回傳：營收 2.89 兆
Thought | 有了去年數字，再查今年前三季來比較
Action | 呼叫工具：查詢財報(公司=2330, 年度=2026, 季=Q1-Q3)
```

想一步、做一步、==讀完結果再決定下一步==，直到任務完成。

## 為何會出現

在 ReAct 之前，[[chain-of-thought|思考鏈]]讓模型會推理了，但那是**閉門推理**——它只能靠自己記得的東西往下想，看不到外面的世界。結果就是：推得很流暢，但引用的數字是編的。

反過來，[[tool-use|工具呼叫]]讓模型碰得到外部資料，但一次只是一個孤立的動作，沒有「拿到結果之後該怎麼辦」。

ReAct 把兩邊接起來，回答了那個工程問題：**什麼時候該停下來查、查哪一個、查完怎麼接回任務。**

## 金融背景怎麼理解

這就是**一個稱職的分析師實際的工作方式**。

不是「先想好全部再一次查完」，而是：查一個數字 → 發現不對勁 → 換個角度再查 → 修正判斷。==每一步都要看前一步的結果，才知道下一步該做什麼。==

它的重要性在於：**今天所有 AI 代理的操作方式，都是這個迴圈的變形。** [[agent-loop|代理迴圈]]就是把 ReAct 從一篇論文變成一支真的會跑的程式，加上輪數上限、錯誤處理、和紀錄。

> [!提醒] 它同時放大了能力和風險
> 「讀結果再修正」是能力的來源——它讓模型可以應付沒預想過的情況。
>
> 但同一個機制也是風險的來源：==每一輪的輸出都會變成下一輪的輸入==，所以一個錯誤的觀察會沿著迴圈傳下去，而且中間沒有人在看。這正是為什麼需要[[human-in-the-loop|人工確認點]]和[[agent-governance|代理治理]]。

實務上的意義：當廠商說「我們的 AI 會自己查資料」，指的通常就是這個迴圈。該追問的是==它跑幾輪、查得到哪些系統、以及每一輪有沒有留紀錄==。
